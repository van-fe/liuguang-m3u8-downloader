# 流光 · M3U8 视频下载

一个 Chrome Manifest V3 扩展：自动发现当前网页的 M3U8 / HLS 和 X（Twitter）帖子视频，也支持手动添加 MP4 直链。点击「下载 MP4」，在本机下载并保存为 MP4 文件；HLS 视频会先下载分片并合并音视频。

当前版本 **1.2.11**，提供可直接访问的隐私政策和公开源码，并准备 Chrome 应用商店发布材料。同时下载的任务数和排队数量均不设上限，新增任务直接并行处理；保留发现视频优先显示、本地文件改名、授权复用、X 视频、预览、分片并发重试、大文件和本机诊断功能。

项目主页与隐私政策：[流光](https://van-fe.github.io/liuguang-m3u8-downloader/) · [隐私政策](https://van-fe.github.io/liuguang-m3u8-downloader/privacy.html)。问题反馈：[GitHub Issues](https://github.com/van-fe/liuguang-m3u8-downloader/issues)。本项目自有代码按 **GPL-2.0-or-later** 授权，第三方组件继续遵循各自许可，见 [LICENSE](LICENSE) 和 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

公网网站测试结果及当前适用范围见 [SITE_TEST_RESULTS.md](SITE_TEST_RESULTS.md)。已验证公开 HLS 下载，以及一个 X 公开视频样例的 MP4 直链、HLS 和新会话手动帖子链接下载。X 原站页面在测试环境返回 403，页面观察器采用受控响应单独验证；不能据此宣称真实 X 时间线自动检测已全面通过。B 站样例使用 DASH，当前不支持，其他站点还可能受登录、地域或人工验证限制。

## 安装与使用

需要 **Chrome 116 或更新版本**。

1. 打开 Chrome，在地址栏输入 `chrome://extensions/`。
2. 打开右上角「开发者模式」，点击「加载已解压的扩展程序」。
3. 选择已解压的扩展文件夹（本地构建输出为 `dist/liuguang-m3u8`）。所选文件夹中应直接包含 `manifest.json`。
4. 将「流光 · M3U8 视频下载」固定到工具栏。
5. 打开视频网页并播放视频。首次安装后，已打开的页面建议刷新一次。
6. 点击插件图标，在「发现视频」中点击 **下载 MP4**；随后可在「下载任务」中查看进度。

每个视频源都提供「预览」按钮，可以先在新标签页播放，确认画面后再下载。手动添加链接后也可以点击「预览」。预览不会自动创建下载任务。

打开插件时，如果当前网页已检测到视频，优先显示「发现视频」；当前网页没有检测到视频且有进行中的任务时，显示「下载任务」。点击下载后会切换到任务进度，后台刷新会保留手动选择的标签页。

「发现视频」中的名称也可以点击编辑，Enter 或失焦保存，Esc 取消。修改后，下载会直接使用该名称；重新检测和关闭再打开插件不会用自动检测的标题覆盖自定义名称。该名称只对应当前标签页中的视频，清空检测列表或导航到新网页后会移除。

没有可用名称时显示「未命名视频」，可自行填写，或点击「使用网页标题」读取当前网页此时的 `document.title`。不会静默选择旧标题；网页标题为空或页面不可读取时会显示提示。手动添加链接的文件名旁也可选择使用网页标题。开始下载前会提交当前卡片中的名称草稿；预览后下载也会优先使用仍在发现列表中的最新名称。

「下载任务」列表支持单独移除和清空：鼠标移到任务卡片上时，右上角显示关闭按钮；列表顶部提供「清空列表」。键盘聚焦关闭按钮时也会显示，触屏设备可直接看到按钮。进行中的任务被移除或清空时会同时取消，已保存的视频文件和独立诊断日志会保留。清理结果会保存，重新打开弹窗后不会恢复被移除的任务。

任务名称默认显示为普通文字，点击后可直接编辑；按 Enter 或移出输入框保存，按 Esc 放弃。尚未保存的任务会用修改后的名称保存为 MP4。文件正在交给 Chrome 保存时暂时不能编辑。

已完成的任务也支持修改磁盘上的文件名：第一次改名时，当前任务卡片直接显示新的文件名、文件夹路径和「选择文件夹并改名」按钮。点击后在 Chrome 的系统选择框中选择该视频实际所在文件夹并允许读写，完成后直接改名，不打开单独授权页面。之后在任务卡片中改名时，会在你提交名称的用户操作中恢复已保存目录的临时授权，再执行原地改名，通常无需重新选择文件夹。若权限被明确拒绝或撤销，可主动点击「重新授权文件夹」，仍在当前弹窗内操作。取消选择或授权、文件不存在、文件不匹配或目标名称已存在时，会显示提示并保留原任务名称。

本地改名调用浏览器的原地重命名能力，不重新下载或复制整个视频，也无需安装额外程序。若当前 Chrome 不支持此能力，会明确提示，不自动改为复制后删除。Chrome 自己的下载历史不会同步更新改名后的路径，因此已改名的任务显示当前本地文件名，不再使用旧下载记录的「在文件夹中显示」按钮。所选目录句柄保存在插件本机存储中，实际路径与文件名不写入诊断日志。

构建也会生成 `dist/liuguang-m3u8.zip`。分享或转移到另一台电脑时，先解压 ZIP，再加载其中含 `manifest.json` 的文件夹。Chrome 的「加载已解压的扩展程序」不能直接加载 ZIP。

下载完成后可点击「在文件夹中显示」。插件底部「下载设置」提供 **自动保存到本地** 开关：

- 开启后，点击「下载 MP4」按 Chrome 下载设置保存；Chrome 未开启「下载前询问每个文件的保存位置」时，直接保存到默认下载目录。若开启了浏览器的询问设置，仍会显示保存框。
- 默认关闭，在保存阶段弹出 Chrome 保存对话框，可自行选择文件名与位置。

设置会保存在本机，下次打开插件继续生效。此开关只控制点击下载后的保存方式；检测到视频后仍需点击下载。关闭插件弹窗后任务会继续，Chrome 需保持运行。

自动保存 MP4 时使用视频标题作为文件名；手动添加链接时可填写自定义名称。保存前会清理文件名中的非法字符，重名文件由 Chrome 自动加序号。扩展通过原生下载链接提供名称，并只跟踪自己预登记的本地文件，不注册全局下载命名监听，也不会替其他下载改名。临时任务关联保存在会话存储中，不写入诊断日志。

关闭「自动保存到本地」时仍使用 Chrome 的保存对话框选择位置和名称。在 Chrome 156 中，如果其他扩展的命名监听干预，保存框的预填名称仍可能变为临时编号，可以在保存框中修改；导出诊断 JSON 同样遵循 Chrome 的保存对话框。本次绕开该浏览器问题的兼容处理用于自动保存 MP4。

同一区域显示任务并行方式，并提供分片并发和失败重试设置：

- 「同时下载」固定显示「无上限」，所有新增任务直接并行处理，排队数量也不设上限。每个任务独立下载、合并和取消；旧版本保存的 1～8 个任务限制不再生效。
- 「分片并发」用于单个 HLS 视频的分片，支持 1 / 2 / 4 / 6 / 8 路，默认 4 路。MP4 直链的每个任务按单个流下载到磁盘。
- 「失败重试」针对失败的分片或 MP4 请求，可设置最多重试 0 / 1 / 2 / 3 / 5 次，默认 3 次；其他任务和分片继续下载。分片并发及重试设置从新建任务生效。

未检测到视频时，先播放视频，再点击「重新检测」；也可以展开「手动添加视频链接」，粘贴完整 HTTP / HTTPS M3U8、MP4 或 X 帖子地址，并填写可选文件名。网页中只显示 `blob:` 视频地址时，插件会尝试从网络请求中识别实际媒体地址，无需手动粘贴 `blob:` 地址。

## X（Twitter）视频

1. 在 Chrome 中打开包含视频的 X 帖子，例如 `https://x.com/用户名/status/帖子ID`。`twitter.com` 的对应帖子链接也可以使用。
2. 在网页播放视频，再打开插件。识别出的媒体会标注「X 视频」以及 MP4 或 HLS 格式，可以先预览再下载。
3. 帖子提供多个画质时自动选择可用的最高画质。下载位置仍遵循「自动保存到本地」开关。

也可把 X 帖子链接直接粘贴到「视频或 X 帖子链接」中。手动解析未获取到视频时，请在 Chrome 打开原帖，按网站要求登录并播放，再点击插件的「重新检测」。首次安装或更新插件后，已打开的 X 页面建议刷新一次。

X 支持范围是公开帖子，或当前浏览器登录后已经有权访问、可以正常播放的帖子。插件不要求手动填写或导出 Cookie、访问令牌，也不把帖子或登录信息发送给外部视频解析服务。需要登录、内容已删除、地域限制或站点验证导致无法播放的帖子，需先在 X 网页中处理；此功能不绕过访问限制，也不支持 DRM。X 可能调整页面或媒体接口，具体网站测试结果以 [SITE_TEST_RESULTS.md](SITE_TEST_RESULTS.md) 的记录为准。

2026-11-01 已在独立未登录 Chrome 会话验证 [SpaceX 的公开帖子](https://x.com/SpaceX/status/1845922924315938922)：粘贴原帖链接后保存出 21.802667 秒、1920×1080 H.264 + AAC 的 MP4，并通过完整解码。原帖网页本身返回 403，本次成功路径使用 X 官方公开嵌入元数据和真实视频 CDN；不代表受限制帖子或登录后时间线已验证。

## 已实现的功能

- 通过网络请求地址、HLS 响应类型以及页面资源检测视频；结果按网页标签页展示，并显示工具栏数量角标。
- 视频源和手动链接均可先打开预览，确认内容后再下载。
- 发现视频可在下载前直接点击编辑名称，或选择当前网页标题；自定义名称会沿用到下载文件。
- 识别 X（Twitter）帖子中的 MP4 / HLS 视频，支持粘贴帖子链接并自动选择可用的最高画质。
- 解析主播放列表并自动选择可用的最高画质，处理相对地址和多级播放列表。
- 支持 MPEG-TS、带初始化片段的 fMP4、字节范围分片，以及独立音轨的下载与合并。
- 支持普通 AES-128 HLS 分片、本地解密、密钥切换和显式或序列号 IV。
- 后台多任务同时下载、单个视频最多 8 路分片并发、可配置的失败重试、进度显示、取消和重新下载。
- 下载任务可逐项移除或一键清空；悬停卡片显示右上角关闭按钮，不会删除已保存的视频文件。
- 点击任务名称直接编辑，支持 Enter 保存和 Esc 取消；未保存的任务使用新名称保存，已完成任务在授权文件夹后直接修改本地 MP4 文件名。
- 可在下载设置中开启自动保存到本地，直接使用 Chrome 默认下载目录。
- 本机保留最近 10 次下载的技术诊断日志，可单独导出失败任务或一次导出全部日志。
- 检查带图片前缀的 TS 分片；确认存在连续且有效的 TS 包后再剥除前缀，避免合并时被误识别为 PNG 等图片。
- 支持数 GB 视频，分片和 MP4 使用本地磁盘缓存处理，不设置视频总大小的固定上限。
- 同时下载的任务数量和等待队列均不设上限。

HLS 转换使用本地 FFmpeg WebAssembly 的流复制封装（`-c copy`）：保留原音视频编码，不进行二次压缩；MP4 直链则直接流式保存原文件。MP4 文件能否在某个播放器中播放，仍取决于该播放器是否支持视频原有编码。合并只改变容器，不会提升原片画质。

## 大文件与磁盘空间

HLS 视频分片先写入扩展专用的本地磁盘缓存（OPFS）。FFmpeg 通过 WORKERFS 按需读取输入文件，MP4 输出通过同步文件句柄直接写入磁盘。保存时把磁盘文件交给 Chrome 下载管理器，不会将整个视频或完整 MP4 读入一个 JavaScript 数组。

视频总大小没有固定硬上限，几 GB 的视频也使用同一下载流程，自动保存、预览、并发和重试设置保持不变。实际可处理大小受可用磁盘空间、浏览器资源及视频编码等条件影响。

缓存和保存目录位于同一磁盘时，建议至少预留预计输入视频大小 **3 倍**的可用空间，用于分片、临时 MP4 和最终保存副本。分盘保存时，Chrome 用户数据／临时缓存所在磁盘需容纳输入分片和临时 MP4，目标磁盘也需有足够空间保存最终文件；只给目标盘腾出空间可能仍不够。

任务成功保存、取消或失败后会自动清理缓存。Chrome 或扩展异常退出时留下的缓存会在下次加载下载引擎时清理。已保存到下载目录的 MP4 不会随缓存清理而删除。

## 使用范围与限制

- 支持有结束标记的点播播放列表；不持续录制仍在更新的直播。直播结束且网站提供完整点播清单后可再试。
- 不支持 DRM、SAMPLE-AES、缺失分片或无法读取密钥的资源。
- 大文件处理依赖本地磁盘缓存，磁盘空间不足时会停止并显示错误。浏览器仍需要内存处理当前分片、解密与音视频信息，异常大的单个分片或特殊编码仍可能超出浏览器处理能力。
- 某些网站要求登录、短时签名地址、特定 Cookie、Referer 或其他鉴权条件。401 / 403 时请确认当前网页能正常播放，并刷新网页、重新检测地址后重试。扩展会按浏览器规则携带可用凭据，不能保证所有网站均可下载。
- Chrome 内部页面、Chrome 扩展商店等受限制页面无法注入检测脚本。请在普通 HTTP / HTTPS 视频网页使用。
- 退出 Chrome、重载扩展或扩展进程中断会结束处理；不会自动恢复未完成分片，请重新打开页面检测并下载。
- 自动检测可能列出同一视频的主清单和子清单，也可能检测到网页内广告播放器的视频源。下载前可通过来源地址区分。

## 下载失败与诊断日志

出现 `Aborted()`、MP4 合并失败或保存异常时，可以导出本机技术日志排查，无需提供视频链接：

1. 在「下载任务」中找到失败任务，点击 **导出此任务日志**；也可在底部「下载设置」中点击 **导出诊断日志**，导出最近 10 次下载的记录。
2. 在 Chrome 保存对话框中保存 `liuguang-diagnostics-日期-时间.json`。导出文件仅包含诊断报告，不包含插件的检测列表或完整任务状态。
3. 没有可导出的记录时，插件会提示暂无日志；重新发起下载并复现问题后再导出。

日志只在本机保存，保留下载阶段、错误及媒体处理等技术诊断信息，**不记录或导出视频及网页地址、域名、帖子编号、标题、Cookie 或登录令牌**。插件不会自动上传日志。记录上限为最近 10 次下载，较早记录会被替换。

「清除日志」会直接清除本机诊断记录，不会删除已经保存的视频或此前导出的 JSON 文件。导出失败或文件保存被中断时会显示提示，可再次点击导出。

某些网站把 TS 分片放在图片文件头后，并以 `image/png` 等类型返回。扩展会对分片明文进行有界嗅探，验证 TS 包结构后才移除图片前缀；AES-128 分片先解密再检查。该步骤按数据流处理，不把完整视频读入内存，也不按固定字节数裁切。初始化分段和已知 fMP4 输入不会被当成 TS 裁切。

如果响应确实只有图片、找不到可信 TS 数据，扩展会显示明确的分片内容错误。诊断日志中的 `resource-normalized` 仅记录内部分片编号、移除的字节数及容器类型，不记录地址、前缀内容或视频数据。

## 本地构建

开发环境需要 Node.js 18 或更新版本及 npm。在项目目录运行：

```powershell
npm ci
npm run build
```

产物：

```text
dist/liuguang-m3u8/      可直接加载的完整扩展
dist/liuguang-m3u8.zip   便于传输的压缩包
```

FFmpeg JavaScript、Worker 和 WebAssembly 都会随扩展一起打包，使用时不需要额外安装 FFmpeg，也不从 CDN 加载可执行代码。首次开发构建需要下载 npm 依赖，因此需要网络。

## 验证

```powershell
npm test
```

单元测试覆盖 HLS 解析、清晰度选择、下载与解密等核心逻辑。

多任务并行回归测试运行 `npm run test:concurrency`：使用独立 Chrome 会话与本地视频，验证超过旧版数量上限的任务实际同时传输、旧配置兼容、取消隔离以及 MP4 保存。临时配置、视频和缓存放在项目的 `work/concurrency-e2e/`，完成后清理临时工程，仅保留精简结果。

端到端测试需要本机 `ffmpeg`、`ffprobe` 命令可用。Windows 安装了标准路径的 Chrome 时，会使用其独立测试配置；也可用 `E2E_CHROME_PATH` 指定 Chrome 路径。其他环境需安装 Playwright Chromium：

```powershell
npx playwright install chromium
npm run build
npm run test:e2e
```

端到端测试在本地生成测试视频、启动 HTTP 服务，通过真实浏览器扩展执行检测、预览、并发重试和 MP4 保存，再检查音轨、画面、时长及解码。某些 Chromium 构建不包含 H.264/AAC 解码器，此时预览测试需要指定正式 Chrome。测试只使用项目内独立的浏览器配置，不会修改日常 Chrome 配置。测试用的本机 FFmpeg 仅用于生成或检查样本；扩展日常运行使用包内的 WebAssembly 引擎。

大文件完整测试可运行 `npm run test:large`，默认实际保存至少 2.1 GiB 的 MP4，并检查音画轨道、尾部解码和缓存清理。PowerShell 中运行 `$env:E2E_LARGE_GIB='4.1'; npm run test:large` 可覆盖 4 GiB 文件偏移边界。该测试会临时占用数 GB 磁盘空间，结果保存在 `test-results/large/result.json`。

本地文件改名测试运行 `npm run test:rename`，使用实际下载的 MP4、真实目录句柄和 Chrome 原生重命名操作，另以超过 4 GiB 的稀疏测试文件检查文件大小、文件标识与首尾数据。测试配置预授目录读写权限，并用真实目录句柄替代系统目录选择框；不声称验证了系统授权弹框的交互。结果位于 `test-results/local-rename/result.json`。

目录授权复用回归运行 `npm run test:permission`，使用 Chrome 真正的工具栏弹窗和默认文件系统权限设置。关闭所有扩展页面后，验证已保存目录的权限退回 `prompt`，再从新弹窗通过 Enter 或失焦提交名称，恢复授权并实际改名，不重新选择目录或打开授权页。首次测试目录通过真实目录拖放和弹窗中的用户点击授权，不声称验证了系统目录选择框。结果位于 `test-results/local-permission/result.json`。

X 公网样例测试运行 `npm run build` 后执行 `npm run test:x`，需要联网和本机 Chrome、`ffmpeg`、`ffprobe`。它会验证真实 CDN 的 MP4 / HLS 下载、媒体解码、预览和新会话手动帖子下载。真实 X 页面不可访问时，观察器部分会改用包含真实公开元数据的受控页面响应，并在 `test-results/x/result.json` 中明确记录；不能把该部分当成真实 X 页面自动播放测试。详细结果见 [SITE_TEST_RESULTS.md](SITE_TEST_RESULTS.md)。

## 权限与数据

| 权限 | 用途 |
| --- | --- |
| `webRequest` | 观察网页视频请求地址和响应类型，识别 HLS 清单及 X 的媒体请求。 |
| HTTP / HTTPS 主机访问 | 检测不同网站，以及请求分布在其他域名上的清单、分片与密钥。 |
| `downloads` | 通过 Chrome 下载管理器保存 MP4，并定位保存文件。 |
| `storage` | 保存设置，以及当前浏览器会话中的检测结果、任务状态。 |
| `unlimitedStorage` | 让扩展的 OPFS 磁盘缓存免受普通站点配额和自动驱逐限制，以处理大视频；实际可用容量仍取决于磁盘空间。 |
| `offscreen` | 在弹窗关闭后继续处理分片，运行本地转换并生成下载 Blob。 |
| `scripting` | 用户点击重新检测或使用网页标题时，为可访问的网页补充扫描脚本或读取当前标题。 |
| `tabs` | 识别当前标签页、网页标题与来源，按页面显示检测结果。 |

插件不上传视频、不设置统计或追踪服务。网络访问用于向资源所属网站请求清单、视频分片、音频和密钥；处理发生在本机浏览器内。检测列表中的签名视频地址可能含有访问令牌，请勿直接分享这些地址；诊断记录和导出文件不包含这些地址。

设置保存在 `chrome.storage.local`；检测结果和任务状态保存在 `chrome.storage.session`，不会通过 Chrome 同步上传。标签页关闭或导航时会清理对应的检测列表；清空检测列表不删除已保存的 MP4。

本地文件改名使用用户主动选择并授权的文件夹，目录句柄保存在扩展自身的 IndexedDB 中。此授权独立于清空下载任务和诊断日志，Chrome 可以重新要求授权；插件不会自动扫描目录或上传目录内的文件。

技术诊断记录保存在本机，最多保留最近 10 次下载，可通过「清除日志」删除。导出仅读取单独的诊断报告接口，不合并含来源地址和标题的下载任务状态；诊断记录不包含视频／网页地址、域名、帖子编号、标题或账号凭据。

下载分片和临时 MP4 保存在该扩展独有的 OPFS 中，不会上传。它们可能在处理过程中持续占用磁盘，在成功保存、取消、失败或异常退出后的下次引擎加载时自动清理。`unlimitedStorage` 对扩展磁盘存储的作用见 [Chrome 权限说明](https://developer.chrome.com/docs/extensions/reference/permissions-list) 和 [扩展存储与 Cookie 文档](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)。

## 实现位置

```text
extension/background.js   请求检测、状态管理、Chrome 下载
extension/content.js      页面资源补充扫描
extension/x-observer.js   X 页面媒体响应观察
extension/offscreen.js    后台任务队列、本地 FFmpeg、Blob 生命周期
extension/lib/hls.js      HLS 清单解析
extension/lib/download.js 分片下载、AES-128 解密、本地清单与封装参数
extension/lib/x-media.js  X 媒体信息与清晰度解析
extension/lib/x-resolver.js X 帖子链接解析
extension/popup.*         中文插件界面
extension/preview.*       HLS 预览播放器
extension/lib/local-downloads.js  本地目录句柄与原地文件改名
scripts/                 构建与端到端验证
tests/                   单元测试
```

架构采用 [Chrome Offscreen API](https://developer.chrome.com/docs/extensions/reference/api/offscreen)，以在隐藏扩展文档中执行需要 DOM / Blob 的处理；本地 WebAssembly 通过 [Chrome 扩展 CSP 中的 `wasm-unsafe-eval`](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy) 启用。大文件缓存使用 [OPFS 和同步文件访问](https://web.dev/articles/origin-private-file-system)，输入通过 [Emscripten WORKERFS](https://emscripten.org/docs/api_reference/Filesystem-API.html#workerfs) 按需读取。媒体引擎使用 [ffmpeg.wasm](https://ffmpegwasm.netlify.app/docs/overview/)。第三方组件及许可证见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
